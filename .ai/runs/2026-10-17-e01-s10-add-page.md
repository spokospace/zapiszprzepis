# Execution plan — E01-S10 add recipe on a dedicated /dodaj page

Source doc: .ai/specs/2026-10-17-e01-s10-add-page.md

## Goal

Signed-in users add a recipe on `/dodaj` (A7, style 1c). Users without full access see screen 3c there. The header, home tile, MENU and add errors all lead to `/dodaj`.

## Scope

- New: `src/app/dodaj/` (layout, page, `AddFromLinkForm`), `src/lib/extract-url.ts`, and `ADD_RECIPE_PATH` / `addRecipeErrorPath` in `src/lib/routes.ts`.
- Changed: `AccessCodeGate` (`unlocked` slot), `app-header.tsx` (href only), `home/member-tiles.tsx`, `app-menu-model.ts`, `add-recipe-action.ts` and `share/route.ts` (error targets).

## Non-goals

- Removing the home add form, or any other `src/app/page.tsx` edit (S15/S17 are working on it in parallel).
- The add-from-photo flow. Any change to extraction, dedup, access rules or the DB (no migration).

## Implementation Plan

### Phase 1: /dodaj page

1. Extract the shared URL helper (`extractFirstUrl`) from the share route, with tests.
2. Add `ADD_RECIPE_PATH` and `addRecipeErrorPath` to routes, with tests.
3. `AddFromLinkForm` client component, with tests.
4. `AccessCodeGate` `unlocked` slot, with a test.
5. `/dodaj` layout and page (access branch, noindex), with tests.
6. Repoint the header, tiles and MENU links and the action/share error redirects. Update their tests.
7. Run the full gate and check the dev server as qa-full, qa-free and a guest.

## Risks

- Tests asserting `/?add_error` must move in the same commit as the redirects.
- S15/S17 touch `app-header.tsx`: a one-line href change keeps the conflict risk small.
